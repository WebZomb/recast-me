## Implementation

`src/router.js` now wraps the existing application in one external response boundary. Its existing imports, routing decisions and engine selections remain. The actual deployed entry point is still src/router.js; root-level duplicate files were not edited. Existing generation, stored clean artwork, fulfillment records and commerce integration code were not replaced.

- `src/preview-security.js`: server-flattened preview derivatives, allowlisted customer metadata, protected retrieval and old mockup/social responses, private refinement preparation, strict paid digital and final-print gates, protected diagnostics, private/no-store response headers. Failure never falls back to returning clean pixels. New inference is blocked before the provider call when the required Images binding or private storage is missing. Already cached protected previews can remain available without new image processing.
- `src/watermark-tile.js`: embedded small raster brand tile and footer using @RecastMeAi, not a font or a customer image. Repeated translucent branding plus purple/cyan footer is flattened into a JPEG no larger than 768 x 960. Aspect ratio is retained. Cloudflare raster output still needs actual visual verification.
- `src/render-controls.js`: optional shared UTC-day AI.run call ceiling using conditional R2 reservations. Every actual inference submission, including same-model retries and uncertain failures, consumes a slot. Simultaneous requests cannot use an unconditional read/overwrite counter. Storage or malformed configuration failures stop calls rather than bypassing the guard.
- Identical client-attempt ID plus canonical form/file hashes receives one durable submission claim. Replaying the same submission returns 409 instead of another inference. The refreshed Turnstile challenge and multipart boundary are excluded from identity. No customer result or access token is retrieved through this claim.
- Private refinement uses the saved clean image inside the Worker, not the watermarked browser image. Selected approved original bytes are not regenerated by this patch for paid download/fulfillment.

Only preview delivery is uniformly protected; static marketing imagery in the public repository is not private customer artwork and is not put behind a paywall.

## Activation gate — important

The repository's Images binding is commented out; live dashboard bindings could differ and were not visible here. Do not merge or deploy blindly: without IMAGES, new renders and uncached preview delivery deliberately stop. Confirm this binding in a preview deployment first, test a non-customer sample through actual image processing, inspect the flattened downloaded image, and check mobile history/refinement/mockups before public activation. Never weaken fail-closed protection just to turn readiness green.

The non-secret variable `AI_DAILY_CALL_LIMIT` activates the request ceiling. Unset means no configured ceiling; `0` disables new AI submissions; a non-negative integer up to 100000 is accepted. The owner has not selected an allowance, so no value was invented or added to wrangler.jsonc. Owner tests, public rendering and scheduled AI calls share this ceiling. It is not dollars, does not cover Images/R2/Workers/X/commerce costs, and does not enforce 20 renders per customer. A total monetary budget and verified-user allowances remain separate work.

Images transformations are a separately metered Cloudflare service. No Images call, billable inference, account upgrade or setting activation was made here. A bundle/dry-run is not a production deployment.

## Remaining limitations and risks

- Mocked image fixtures validate routing and transform contracts, not visible pixels, real provider behavior, print quality or Cloudflare cross-region concurrency. Inspect actual derivatives before activation.
- Duplicate rejection is not durable background rendering or completion recovery. Legacy clients without clientAttemptId are not deduplicated. A new deliberate attempt ID is a new request. Scheduled social crash/retry idempotency still needs reconciliation. Claims persist conservatively; retention and bounded cleanup need a separate policy.
- A render can be saved privately before image processing fails. Recovery by an already authorized ID is tested; automatic discovery/resume of a just-completed lost response is not implemented. Existing last-successful-version UI is unchanged.
- Paid gating honors explicit revoked/refunded metadata, but the existing order sync does not implement comprehensive refund/cancellation webhooks or per-buyer entitlement reconciliation. Do not claim refunds automatically revoke access. Validate the full commerce loop before launch.
- Old print-service capabilities already exposed by earlier versions are not rotated by this patch. Plan capability rotation/expiry and verify fulfillment use before activating commerce. Previously downloaded clean bytes cannot be retracted.
- The client currently adds its own decorative watermark; with a server mark it may look too dense. Review and remove only redundant decoration later, never the server-side mark.
- This is a focused protection patch, not a penetration test or proof that every future API response is safe. Audit new routes against the wrapper, including nonstandard binary formats and raw fields. Watermarks are not a guarantee against external image editing/removal.
- Live binding status, deployment identity, browser/Safari behavior, real purchase, Printful sample, X posting and updated provider comparisons remain unverified.
