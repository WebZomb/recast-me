## Actual implementation (code, not just a plan)
- `public/index.html`: AI wizard now has only **1 · Photos → 2 · Style**. Removed the required Who screen entirely and its large 7-category tile selection. Existing AI/original-photo selector at top remains prominent, original upload path unchanged. The auto subject select is `auto` by default; optional collapsed “Help with group photos” holds manual subject types and the family-count field for complex multi-person cases. Defaults do not insert sex/gender tags or any unsupported labels. For one photo or no help, none of the “Photo 1 shows: Your pet” UI is shown. Privacy consent remains mandatory but moves immediately above the final create action; full third-party AI provider notice remains available in optional privacy details.
- `public/creation-wizard.js`: automatic two-step selection starts at photo upload; never jumps the homepage automatically on initial load. Photo identity tags are optional, shown only when a customer deliberately selects a mixed/group type and has multiple uploads. If all photos are intentionally labeled, existing `referenceDirections` server-side validation still applies; otherwise no guesswork labels are sent and the model uses the originals. More Styles and Surprise Me, all 48 adventures, current reference/photo validations and original-photo product route remain.
- `src/identity-first-adventure-prompt.js`: **no separate image classifier or inference call**. Existing HQ fal FLUX.2, HQ Cloudflare fallback and Standard Klein render models receive an *automatic, conditional photo-grounded prompt*: inspect actual reference image, preserve the exact pet or person features (and vehicle parts) **as appropriate**, choose only the real subject's wardrobe, avoid invented people/pets/gender assumptions, don't redesign the face. The 48 unique scenes and wardrobe guides remain, no new customer fields or backend quotas changed. Prompt identity accuracy is NOT mathematically guaranteed; subjective image QA is still required.
- `public/app.js`: sends `subject=auto` by default, only submits customer-supplied identity labels when complete, updates concise photo count, starts/refines at Photos, hides redundant "selected: Royal" badge when a featured style is visibly outlined and still names Surprise Me's actual result. No duplicated “High Quality used” availability text on step 1, no second disabled HQ action when Standard eligible. One clear “Use Standard (lower detail)” choice enables the existing Standard model, with face-likeness caveat visible; provider gate still verifies server eligibility and explicit opt-in. When 0 credits, a dead generate action stays hidden and full reset times remain in collapsible details. Existing passed server credit/budget/auth rules untouched.
- `public/simple-flow-v117.css`: responsive mobile-first touch targets, succinct photos panel, unobtrusive optional complex-photo help, compact credit/fallback disclosure and one actionable button at a time.
- `scripts/rm050-browser-tests.cjs`: exercises WebKit iPhone, Chromium mobile/desktop two-step wizard; actual photo upload without bogus forced label (including two references); optional group tagging, switching back to auto, optional 48 adventures, exhausted/available Standard state and absence of duplicate alerts.
- `tests/simplified-creator.test.mjs`, `tests/render-wait-ui.test.mjs`, `tests/adventure-prompt-audit.test.mjs`: static and mocked provider tests enforce two-step UI, default auto mode, image-grounded short prompt across 48 worlds, no extra provider cost, unchanged safety and Standard/HQ models.
- `src/reference-labels.js` server validation and existing exact explicit user-group labels preserved; `src/commerce-store.js`, customer wallets, Printful/Shopify order pipeline, merchant/admin credits, social bot, human verification and moderation unchanged.

## Risks, testing and release gate
**Not a new vision classifier.** The already-used photo editing model will read its photo input and apply conditional instructions; classification may be uncertain if the customer uploads a screenshot with a tiny subject, a collage, or a complex group. Advanced group tagging is available when needed, but not required. Never infer or ask for sex/gender. Keeping the original face precisely requires provider features such as masked region editing (separate investigation and owner budget review); do not claim this change solves face drift.
GitHub PR CI includes existing 447+ mocked Node tests, Wrangler dry-run and no-charge Safari WebKit/Chromium browser flows; **no live HQ provider image generated, no customer balance spent, and no checkout order made**. Note any test failures honestly, resolve before merging, verify guarded Cloudflare deploy and read-only live smoke. The original-photo/no-AI route should be unchanged; manual owner iPhone test will confirm.
