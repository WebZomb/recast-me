# Recast-Me RM104 — 48-adventure prompt and description audit

## Why this pass
The owner supplied actual **Standard** results: **Holiday Magic** was effectively the original yard photo with little seasonal transformation; **Rock Star** stylized the pet into a partial cartoon but left the unchanged backyard instead of a rock concert. This is a theme-compliance problem, not evidence that the reference identity is wrong. The two source photographs are supplied by the user; no customer photos have been exported, used for a paid test, or embedded in repository source.

## Source audit
- The public picker in `public/app.js` has **48** distinct adventure IDs across Featured, Animation & Art, Sports, Music & Fame, Travel & Lifestyle, Careers & Dreams, History & Legends, Decades, Movies & Adventures, Funny & Wild and Seasonal; `custom` is user-authored and handled separately.
- The server in `src/highquality.js` has matching 48 style IDs, but many prior `style.prompt` values were generic and specified only a mood. `SUBJECT_STYLING` covered only nine themes; the other ~39 relied on a generic “costume, role and visual styling” statement.
- More importantly, **Standard on Cloudflare FLUX.2 Klein-9B reused the full multi-thousand-character HQ identity prompt**. That placed theme, new world and wardrobe behind extensive face/coat rules, making it easy for a shorter-context image model to preserve the *whole original photo* or merely apply drawn outlines. This is an engineering hypothesis supported by the input/output and actual request code; model-side attention cannot be proved from the image alone.

## Implementation
- One shared `public/adventure-guides.js` registry now describes **every adventure** with a concrete `scene`, specific `pet` outfit, specific `person` outfit, `look` (photo versus illustrated), and a clear, concise customer-facing `teaser`. Each is a different real location; all unbranded and original. Preset IDs match existing styles. Custom World still uses user text.
- The public `app.js` uses the same registry for cards and shows the chosen adventure's description beside the selector; `index.html` and a small new stylesheet display the caption, improving expectations without changing UI navigation or product ordering.
- New `src/standard-adventure-prompt.js` assembles a SHORT, scene-first Standard prompt: change **the entire original background** to the selected world, outfit the subject for the theme, specify appropriate photographic/illustrative rendering, and preserve the real face/eyes/pet coat/paws. It explicitly forbids “original yard” retention when not requested and generic pet/cartoon substitution. Supports all 48 presets, person/pet/mixed groups, vehicles, prior-version refinement, reference roles and custom world. Does NOT change the Standard model, resolution, number of image submissions or allowance.
- `src/highquality.js` uses the new Standard builder **only** in quick mode. The existing Cloudflare HQ prompt, safety gates, provider error handling, moderation, private storage, credits and watermark code are left unchanged. Source metadata records new `standard-adventure-scenes-v1` prompt version for traceability. HQ fal prompt in `src/fal-prompt.js` gains the same specific scene/pet and human attire cues for consistency, using the existing protected pipeline and settings.
- `tests/adventure-prompt-audit.test.mjs` validates exact 48-ID coverage, scene-specific prompts and wardrobe for each subject category, compact context, new-world replacement, owner-supplied custom directions, correct no-paid-retry and mode settings, themed actual mocked Standard image submission and existing privacy/credit safeguards. Existing `generator.test.mjs` identity assertions remain, while permitting the scene-first compact ordering for Standard.

## QA, scope and rollout
This is a *prompt-only accuracy and presentation update*. It does not perform 48 billable image generations or promise that any generative model will always perfectly follow prompts. The **visual QA** for each World must be checked over time on actual outputs (prefer representative themed renders and record cost/duration); live providers can vary. No external photos, supplier orders, account emails, secrets, credit counters or production model settings were changed. The user said “make sure every option has good descriptions/prompts”, not “buy 48 tests.”
Current public fal High Quality and Cloudflare Standard remain as established. Before deployment, run full mocked regression, security/Chromium/WebKit CI, Wrangler dry-run and update the exact main/Worker version receipts. Reverting this branch restores prior prompts and UI descriptions without changing saved customer artwork or paid orders.
